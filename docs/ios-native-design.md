# 澄音 MusicDL：原生 iOS 设计规范

研究与设计日期：2026-11-08（北京时间）。目标：iPhone 17 Pro Max、用户指定的 iOS 27；同时按系统提供的可用空间适配其他 iPhone。

这份文档先定义设计，再供 SwiftUI 实施与视觉验收使用。具体实现和验收状态以测试记录为准，规范不构成已经实现或真机验证的声明。

## 1. 证据范围与不确定性

| 类型 | 本次可用证据 | 能支持的结论 | 不能支持的结论 |
|---|---|---|---|
| 用户真实设备观察 | 本次未收到 Apple Music 截图、录屏或可操作的 iPhone 会话 | 无直接观察结论 | 不能宣称复原 iOS 27 当前 Apple Music 的像素、弹簧参数或私有布局 |
| Apple 官方用户指南 | 搜索、资料库、播放器、歌词及队列的公开操作说明；检索结果包含 `/27/ios/27` 页面 | 页面职能、公开可用操作与基本内容层级 | 不能证明所有地区、订阅、版本和账号的显示完全相同 |
| Apple 官方 SwiftUI/HIG/WWDC | Liquid Glass 使用原则、系统 TabView、底部 accessory、sheet、玻璃容器与辅助功能 | 合法公开原生组件及设计原则 | 不能推断 Apple Music 内部源码或私有 API |
| Go Music DL 源码 | 已有音源、搜索、收藏、下载、歌词、本地音乐、设置与后台播放实现 | 本项目真实功能与可复用架构 | 不等于所有音源在目标设备上都能成功访问 |
| 本文设计数值 | 下文给出的间距、圆角、颜色、字体、动效时长 | 澄音的独立设计决策，可用于实施 | **不是对 Apple Music 的测量值** |

本设计吸收的是内容优先、控制可达、上下文连续、原生手势一致等原则。不会将 Apple 的 Logo、品牌标题、专辑示例图、编辑文案、宣传素材或专有动画资源打包到本应用。

## 2. 公开参考研究

以下均为公开文档事实或基于公开资料的设计推断，**没有 iOS 27 Apple Music 实机动态界面观察**。

| 参考区域 | 官方资料能够确认的公开行为 | 设计推断 | 澄音采用的独立方案 |
|---|---|---|---|
| 首页/发现 | Apple 指南将个性化推荐和新音乐/榜单等浏览作为不同找歌路径。[R1] | 编辑式内容分组能降低大量歌曲的扫描成本 | 一个“发现”页：轻量品牌抬头、最近聆听、真实推荐歌单、排行榜；不伪造个性化算法或订阅内容 |
| 搜索 | 官方搜索包括分类、最近搜索、曲目/艺人/歌词等关键词，以及目录/资料库范围。[R2] | 输入前和输入后应有不同布局 | 搜索前呈现最近关键词与来源；输入后显示歌曲/专辑/歌单类别、音源筛选及明确请求状态 |
| 音乐库 | 官方指南按歌单、艺人、专辑、歌曲和已下载等类别组织个人内容。[R1] | 个人内容需要稳定、可预测的入口 | “音乐库”突出收藏歌单、下载、本地音乐与最近播放；每个入口都打开原生详情 |
| 迷你播放器 | 显示当前曲目，含暂停/下一首；点击打开正在播放页。公开指南也描述标题区域横滑切换曲目。[R3] | 持续可达的播放控制可减少导航中断 | `tabViewBottomAccessory` 放置封面、曲名、艺人、播放/暂停及下一首。横滑只作用于文字/封面区域，不覆盖按钮命中区域 |
| 全屏播放 | 官方正在播放页提供进度、上一首/下一首、歌词、输出设备和队列等控制。[R3] | 主内容和次要操作需要明显分层 | 大封面/歌词/队列三种内容状态；核心播放键固定在下部拇指区域，收藏/更多是次要动作 |
| 同步歌词 | 有逐行时间信息时自动同步；没有时可能显示整段文本。[R4] | 缺少时间信息不应假装逐字同步 | 有 LRC 时间戳则逐行跟随；支持逐字数据时才逐字强调。普通文本明确按全文展示；无歌词有独立空状态 |
| 队列 | 官方文档描述查看接下来播放、拖动排序、移除、清空和查看历史等操作。[R5] | 队列是可编辑的播放计划，不是搜索结果列表 | 原生列表、当前曲目标记、拖动排序、左滑移除、下一首播放/加入末尾；清空需确认 |
| 弹窗与手势 | SwiftUI 系统导航、sheet、菜单提供平台一致的交互；iOS 26 的部分高度 sheet 默认采用新材质。[R6] | 同一语义应使用同一系统容器 | 详情使用 NavigationStack；二级任务用 Sheet；歌曲动作使用 Menu/contextMenu；破坏动作使用 confirmationDialog |
| 深浅色 | 系统 Liquid Glass 会响应环境与辅助功能设置，HIG 将其放在导航/控制层。[R7] | 内容底色应稳定，不能让玻璃成为内容本体 | 暖纸白/墨深色内容底，系统控制自适应；不手动重造系统玻璃的折射或模糊 |

“Telegram 的流畅”在本项目中表示及时响应、手势不中断、列表位置保留和可取消的加载；本次未对 Telegram 客户端做逆向或帧率测量，不宣称达到某个第三方的内部性能参数。

## 3. 独立品牌与视觉方向

**品牌名：澄音 / MusicDL。** 界面主名“澄音”，关于页保留 Go Music DL 项目来源与许可署名。

体验关键词：温柔、安静、清晰、封面优先、细节精确。图像是音乐封面，颜色是少量引导，玻璃是控制的材质。

### 3.1 颜色

这些是本应用的独立设计 token，非 Apple Music 取色值。

| Token | 浅色建议 | 深色建议 | 用途 |
|---|---|---|---|
| `canvas` | `#F7F5F1` | `#111315` | 主内容底色，浅色略暖、深色略带墨色 |
| `surface` | `#FFFFFF` | `#1D2023` | 内容分组、表单、没有封面的实体卡片 |
| `ink` | 系统 primary，近 `#202326` | 系统 primary，近 `#F3F1EC` | 主标题、曲名、核心数值 |
| `secondaryInk` | 系统 secondary | 系统 secondary | 艺人、专辑、辅助说明；不依赖固定低透明度 |
| `accent` | `#C95648` | `#F08D7F` | 当前选择、主要按钮、进度强调；少量使用 |
| `softAccent` | `#F4E3DD` | `#332622` | 品牌插画/空状态的实色底层，不模拟玻璃 |
| `separator` | 系统 separator | 系统 separator | 列表关系、表单边界 |

封面背景只作为播放页的氛围层；歌词、按钮与状态文字始终有稳定的对比底层。高对比度与减少透明度模式优先使用系统语义颜色和不透明内容底。不要让珊瑚色文字承担长篇阅读内容。

### 3.2 字体

使用系统字体与 Dynamic Type，不打包 Apple 私有字体。中文由系统字体回退处理。

| 层级 | 默认建议 | 语义及行为 |
|---|---|---|
| 页面大标题 | `.largeTitle.bold()`，约 34 pt | 发现/搜索/音乐库；系统导航栏可自然收缩 |
| 品牌/编辑标题 | 28–32 pt，semibold/bold | 发现页首屏的一处重点，避免到处放大标题 |
| 分组标题 | `.title3.weight(.semibold)`，约 20 pt | 最近聆听、榜单、收藏歌单 |
| 歌曲标题 | `.body.weight(.medium)`，约 17 pt | 默认一行，大字模式允许两行并增长行高 |
| 艺人/辅助文字 | `.subheadline`，约 15 pt | 默认一行，可访问尺寸不强制挤成一行 |
| 元信息/音质/时长 | `.caption`/`.caption2`，约 12–13 pt | 使用等宽数字显示时长；不要把主要状态放在极小文字里 |
| 播放页歌名 | `.title2.weight(.bold)`，约 24 pt | 可两行，不与收藏按钮重叠 |
| 活动歌词 | 28–32 pt，bold | 基于 Dynamic Type 缩放；当前句最清晰，邻句保持可读 |

### 3.3 间距与尺寸

全部使用 point 与系统布局空间，不把 iPhone 17 Pro Max 的像素尺寸写死。

| 项目 | 默认设计值 | 自适应规则 |
|---|---|---|
| 页面横向留白 | 24 pt | 紧凑宽度可缩至 20 pt；大字模式保留至少 16 pt |
| 页面分组间距 | 28–32 pt | 不以增加空白挤掉首屏核心入口 |
| 标题与内容 | 12–16 pt | 同一层级一致 |
| 卡片间距 | 12–16 pt | 自适应网格两列；极大字/横屏可变一列或三列 |
| 歌曲行 | 默认 68–76 pt | 根据文本增高，不固定卡住 Dynamic Type |
| 歌曲行封面 | 52–56 pt 方形 | 圆角 10–12 pt，保持图片比例 |
| 迷你播放器封面 | 40–44 pt | 圆角约 8 pt；控件点按区至少 44×44 pt |
| 专辑/歌单卡片封面 | 列宽内正方形 | 封面圆角 16–20 pt，标题在封面下方 |
| 发现重点卡片 | 自适应宽，约 1.35–1.6:1 | 没有真实封面数据时使用原创色面/SF Symbol，不塞入虚假歌曲 |
| 全屏封面 | `min(可用宽度-48, 360)` pt | 竖向空间不足时缩小，横屏不强迫大封面占满屏幕 |
| 命中区域 | 至少 44×44 pt | 图标可以较小，实际可点区域不能缩小。[R8] |

## 5. 页面与交互规格

### 5.1 发现

- 首屏先建立品牌和音乐内容关系，不显示服务器地址、Go 引擎状态或开发参数。
- 最近聆听读取真实本地历史，没有记录时用一句“从一次搜索开始”及“搜索音乐”按钮引导。
- 推荐/榜单区只呈现真实响应；来源暂不可用时该分组展示重试，不把它伪装成全站没有音乐。
- 点击卡片进入原生详情；在歌曲行直接点按播放，长按打开歌曲动作。
- 下拉刷新内容但不清空当前播放、收藏或已选来源。

### 5.2 搜索

- 原生搜索框，键盘 Return 发起请求；保留显式搜索动作，输入防抖不能导致重复昂贵的跨平台请求。
- 查询范围、内容类型、来源是三种不同概念。来源筛选允许多选，展示已选数量及全选/清除；清除全部时明确提示选择来源。
- 不把需要账号的来源静默隐藏。可显示“需登录”状态并跳到对应账号设置。
- 新查询取消或丢弃旧请求结果；分页追加去重，失败时保留前一页。
- 曲目更多菜单包括：下一首播放、加入队列、收藏/加入歌单、换源、下载、查看专辑、来源信息。不可用的动作给出原因。
- 专辑/歌单结果使用封面卡片，详情以封面、元数据、播放全部/随机播放和歌曲列表组成。

### 5.3 音乐库

- 首屏是个人内容，不是管理后台：收藏歌单与最近内容优先，下载/本地音乐为清晰入口。
- 创建歌单使用原生 Sheet，名称校验、保存中禁用重复提交、失败保留输入。
- 歌曲收藏有明确成功状态；删除收藏与删除本地文件是不同动作，文案和确认不能混用。
- 本地文件通过系统文件选择器导入；失败逐项反馈，不以总成功提示掩盖单文件失败。
- 下载列表包含等待、进行中、完成、暂停、失败状态与重试/取消动作；不展示伪造进度。

### 5.4 我的与设置

- 账号列表按来源展示，已配置/未配置/授权过期使用文字+图标，不只依赖颜色。
- Cookie 默认遮蔽；保存成功只确认状态，日志和主界面不回显凭证。
- 二维码登录仅在该来源支持时提供，扫码、等待确认、成功、过期、失败各有状态；可取消轮询。
- WebDAV 使用原生 Form：开关、地址、用户、遮蔽密码、目录、保存结果。没有服务端测试接口时，不放“测试连接成功”的虚假按钮。
- 音质显示来源实际可选能力；不得把“无损优先”设置描述成已经取得或解码了无损文件。
- AI API 保留能力说明、索引/连接信息和可用操作，不把需要技术知识的参数塞进普通找歌页面。
- 原项目的其他高级设置通过可搜索/分组的原生表单保留，不能靠“网页版高级设置”当作全面原生化完成。

### 5.5 迷你播放器与全屏播放

- 原生音频状态是唯一真相：`loading/preparing/playing/paused/interrupted/failed/ended`，不靠定时器猜测状态。
- 无曲目时 accessory 隐藏或显示明确的待播放空状态；不展示虚假的预置歌曲。
- 缓存等待时播放键呈现等待状态但仍可暂停/取消；不能让用户只能反复点“播放”。
- 从封面/文字区域点击展开播放页。横滑切歌需设置方向阈值，不能与系统返回和按钮点按竞争。
- 全屏页下拉可关闭，明确的关闭按钮始终可用；操作队列/歌词内部滚动不误触关闭。
- 拖动进度时只更新预览值，松手后发起一次 seek；原生确认返回后校准时间，避免请求回环。
- 播放模式明确区分顺序、随机、单曲循环；点击切换立即有可访问名称和视觉状态。
- 输出设备使用系统 `AVRoutePickerView`，不模拟 AirPlay 设备列表。

### 5.6 歌词

- 原生 `ScrollViewReader`/列表按音频当前位置确定活动行。用户手动滚动期间暂停自动居中，提供“回到当前”按钮恢复。
- 点击有时间戳的歌词可 seek；纯文本歌词不能伪造跳转时间。
- 正常状态当前行高对比、下一行可预见、历史行适度弱化。不要把所有非当前行降到不可读的透明度。
- 歌词加载、没有歌词、纯文本歌词、解析失败、网络失败均有可解释状态及重试。
- 活动行淡入/颜色变化，避免每个字不断放大、弹跳或晃动。逐字高亮仅在真实数据支持时启用。

### 5.7 队列与弹窗

- 队列行提供可见拖动柄；播放中的行用波形/SF Symbol与文字标识，不以动画作为唯一提示。
- 调整顺序不重播当前歌曲；删除未来曲目不打断当前播放；删除当前曲目的行为必须明确并测试。
- “清空队列”“删除文件”“删除歌单”分别确认，说明影响对象。取消不得改变数据。
- 加入歌单/换源选择使用 Sheet；简单歌曲动作使用 Menu；短暂反馈用轻量提示或行内状态，不用每次弹 Alert。

## 6. 统一状态模型

| 状态 | 视觉表现 | 交互要求 |
|---|---|---|
| 初次加载 | 结构占位或轻量 ProgressView，保持真实页面标题 | 可返回/切 Tab，不显示假内容 |
| 有数据 | 真实列表/卡片 | 点击与更多菜单可执行，分页保持位置 |
| 空数据 | 原创 SF Symbol/简洁色面、标题、原因、一个主要动作 | 区分未创建、无搜索结果、未登录、无下载 |
| 部分成功 | 已成功内容继续显示，失败分组显示原因 | 单独重试失败来源，避免清空整个页面 |
| 网络错误 | 简洁错误说明和重试 | 保留查询与表单输入，不回显敏感请求内容 |
| 权限/授权不足 | 明确“需登录/当前账号无权限” | 跳到对应账号设置；不绕过付费/DRM限制 |
| 提交中 | 操作旁进度，防止重复提交 | 仍可返回；若不能取消，应清楚说明 |
| 已离线 | 可读本地音乐/已缓存内容 | 在线动作明确说明需要网络 |
| 原生播放中断 | 状态与系统一致 | 系统允许恢复且用户没有主动暂停时才恢复 |
| 解码/换源失败 | 歌曲级错误，不静默误播另一首 | 允许换源/重试，显示实际结果 |

## 7. 原生 Liquid Glass 实施边界

### 必须采用

- 系统 `TabView` 的真实导航语义与系统 `NavigationStack`。
- iOS 26+ 使用 `tabViewBottomAccessory(content:)` 承载迷你播放器，系统协调它与浮动 Tab Bar 的关系。[R6]
- 自定义的少数悬浮控制才使用 `glassEffect(_:in:)`；多个需要互动的玻璃形状放在 `GlassEffectContainer` 中。应先完成内容尺寸、padding与形状，再应用玻璃效果。[R9]
- Sheet、Toolbar、Menu 和系统确认框保留系统材质与交互；不再对外层叠加一层假的玻璃。

### 不采用

- CSS backdrop-filter、WKWebView 中的模糊、截图叠层或自制折射 shader 来冒充原生 Liquid Glass。
- 每张专辑卡、每个分组和整页背景都套 glassEffect。Apple HIG 将玻璃定位于导航和控制层，不建议用于一般内容层。[R7]
- 私有 Apple Music 类名、私有 selector、专有字体/素材和未经证实的 iOS 27 私有 API。

### 编译建议

1. 必须实际选择装有 iOS 26 SDK 的 **Xcode 26 或更新版**。仅把运行环境设成 macOS 而继续用 Xcode 16.4，不能编译这些新 API。
2. 真正调用新 API 的代码使用 `if #available(iOS 26.0, *)`，或整个新目标最低 iOS 26。不能只根据设备声称为 iOS 27 而忽略构建 SDK。
3. 基础形态为：

```swift
if #available(iOS 26.0, *) {
    TabView {
        // 发现、搜索、音乐库、我的四个原生页面
    }
    .tabViewBottomAccessory {
        MiniPlayerView()
    }
    .tabBarMinimizeBehavior(.onScrollDown)
}
```

注意正确名称是 **`tabBarMinimizeBehavior`**，不是 `tabViewMinimizeBehavior`。accessory 可以读取 `@Environment(\.tabViewBottomAccessoryPlacement)` 后调整展开/内联内容。先采用 iOS 26.0 的基础 `content:` 形式；若采用带 `isEnabled` 等重载，必须另核对所选 SDK 的准确可用版本。

```swift
if #available(iOS 26.0, *) {
    GlassEffectContainer(spacing: 12) {
        HStack(spacing: 12) {
            Button(action: showQueue) {
                Image(systemName: "list.bullet")
                    .frame(width: 44, height: 44)
            }
            .glassEffect(.regular.interactive(), in: .circle)
        }
    }
}
```

以上是实施建议，最终以选定 Xcode SDK 的实际编译为准。不要把 `.ultraThinMaterial` 的旧系统降级方案称为 Liquid Glass。

### 封面/播放器连续转场与玻璃形变

公开的跨页面 zoom API 在 iOS 18 引入，也能用于 Sheet 和 fullScreenCover。来源与目标必须使用同一个 `@Namespace` 及稳定 ID：[R11]

```swift
MiniPlayerView()
    .matchedTransitionSource(id: "now-playing", in: playerTransition)
    .fullScreenCover(isPresented: $showPlayer) {
        NowPlayingView()
            .navigationTransition(.zoom(sourceID: "now-playing", in: playerTransition))
    }
```

`matchedTransitionSource` / `navigationTransition(.zoom(...))` 管理页面连续性；`glassEffectID("queue", in: glassNamespace)` 管理 GlassEffectContainer 内部玻璃形状的身份与形变，两套身份不能混为一谈。不要每次视图刷新生成随机 UUID 作为转场 ID。开启减少动态效果时使用无缩放的系统/淡入方案。

## 8. 动效、手势与流畅性

下面时长是澄音的独立选择，非 Apple 的私有参数。

| 场景 | 建议 | 减少动态效果时 |
|---|---|---|
| 按钮/选项状态 | 约 0.15–0.2 秒短反馈，以系统 Button 反馈优先 | 立即状态变化或短淡入 |
| 内容分组切换 | 约 0.2–0.25 秒淡入，不重新滑动整个页面 | 直接替换 |
| 迷你播放器展开 | 约 0.35–0.45 秒系统/弹簧过渡，输入可中断 | 短淡入，不缩放整页 |
| 封面换曲 | 约 0.25 秒交叉淡入/轻微缩放 | 交叉淡入 |
| 歌词定位 | 约 0.25–0.35 秒短滚动，仅活动行变化时执行 | 不做连续自动动画 |
| 玻璃控制形变 | 让系统 glassEffect/Container 处理 | 跟随系统设置 |

不使用无限旋转封面、持续漂移的大背景、到处回弹的卡片和阻止下一次操作的完成动画。Apple HIG 强调短、精确、可选择的动作反馈。[R10]

实现要点：异步请求不阻塞主线程；旧查询用任务取消/版本标识丢弃；列表复用稳定标识；不每秒重建整棵页面；封面缓存并控制解码尺寸；进度更新只影响播放器相关区域；后台不运行动画。帧率与能耗需用实际设备工具测量，不能凭设计宣称“120 fps”。

## 9. 可访问性、安全区域与验收

- 使用系统 Safe Area，不硬编码动态岛高度或 Home Indicator 留白；背景可扩展到边缘，文字与操作不越入传感器区域。
- 键盘出现时搜索和表单可滚动，提交按钮不被遮住。横屏、分屏环境按实际几何布局，不依赖机型字符串。
- 支持 Dynamic Type，至少覆盖默认与辅助功能大字；长中文歌名、长艺人名、没有封面、无歌词都必须测试。
- VoiceOver 为播放/暂停、收藏状态、音源、音质、下载进度、队列排序和歌词行提供明确名称；非必要的每秒时间更新不连续打断朗读。
- 尊重 `accessibilityReduceMotion`、减少透明度及增加对比度；选中态用图标/文字共同表示。
- 关键音乐操作保持可达。全屏详情展开/关闭、列表滚动、队列拖动与系统返回不应争抢同一触摸区域。
- 模拟器浅/深色截图必须覆盖发现、搜索、音乐库、我的、迷你播放器、播放页、歌词、队列及至少一种空/错误状态。
- 真机必须另测 iPhone 17 Pro Max 的动态岛/Safe Area、键盘、大字、AirPods、实际来电、锁屏和至少 30 分钟后台播放。模拟器通知或短 WAV 队列测试不等于真机验收。
